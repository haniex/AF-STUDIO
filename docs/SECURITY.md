# Безопасность AF STUDIO 2.0

## Модель угроз и меры
| Угроза | Мера | Где |
|---|---|---|
| Просмотр платформы без входа | Ничего не рендерится до `auth.getUser()` (серверная проверка JWT). Единый guard в роутере на **каждую** навигацию. `404.html` и `project.html` отправляют любые пути через guard | `js/main.js`, `js/core/router.js`, `js/core/auth.js` |
| «Вход» подделкой localStorage | Токен в хранилище — только кэш; при загрузке он проверяется сервером Supabase, иначе удаляется | `bootstrap()` |
| Доступ к чужим данным | RLS на всех 26 таблицах; клиент видит только строки с `client_id/user_id/owner_id = auth.uid()`; anon не имеет прав ни на одну таблицу | `0002_rls.sql` |
| Повышение привилегий | Роль хранится в отдельной `user_roles` без каких-либо прав записи для клиентов; `is_admin()` — SECURITY DEFINER; в `profiles` нет поля роли; колоночные GRANT на `profiles` | `0001`, `0002` |
| Подмена статуса/владельца проекта | Триггер `project_before_insert` принудительно ставит `status='new'` и `client_id=auth.uid()`; любые UPDATE от клиента запрещены триггером и RLS | `0001_schema.sql` |
| Изменение итоговых файлов клиентом | Клиент не может вставлять файлы `render/final`; в Storage нет UPDATE-политики (нет перезаписи), DELETE — только своих объектов (`owner_id`) | `0002`, `0003` |
| Поддельные ответы «администратора» | `from_admin`, `sender_id`, `author_id` выставляются триггерами на сервере | триггеры messages/review_comments |
| Подделка истории AI | Запись `ai_messages` только Edge Function (service role); клиент может лишь читать/удалять/помечать «сохранено» | `0002`, `ai-chat` |
| Утечка секретов | В браузере только `anon` key. `GEMINI_API_KEY`, `SERVICE_ROLE`, `RESEND_API_KEY` — Supabase secrets | `js/config.js`, `functions/*` |
| Злоупотребление AI | Лимиты в минуту и в день (атомарная `ai_consume`), макс. длина, ограничение контекста, таймаут 45 с, CORS-whitelist | `ai-chat`, `ai_settings` |
| Prompt injection в AI | Системные правила: отвечать только по базе знаний, не выдумывать цены/отзывы, не раскрывать инструкции; цены — только из `pricing_*` | `ai-chat` |
| Спам формами | Honeypot-поля (регистрация, конструктор), защита от двойной отправки, серверные лимиты: 5 заявок/час, 20 сообщений/5 мин, 10 обращений/час, 60 файлов/час | `access.js`, `builder.js`, триггеры |
| XSS | Все пользовательские данные выводятся через `html```(автоэкранирование); Markdown AI — экранирование до разметки, ссылки только `https?`; CSP без `unsafe-inline` для скриптов; данные мудборда санитизируются | `core/ui.js`, `index.html` |
| Загрузка опасных файлов | Белый список MIME + лимиты размера в браузере **и** в настройках бакетов; приватные бакеты, подписанные URL на 1 час | `api.js`, `0003_storage.sql` |
| Перебор паролей / спам регистраций | Встроенные rate limits Supabase Auth; подтверждение email | Supabase Auth |
| Перечисление аккаунтов | «Забыли пароль» всегда показывает одинаковый ответ; ошибки Supabase не показываются пользователю | `auth.js`, `errors.js` |
| Захват сессии после выхода | `signOut` (local/global) + очистка токенов из обоих хранилищ; «Выйти на всех устройствах» в настройках | `auth.js`, `settings.js` |
| Удаление аккаунта | Только через Edge Function: пароль + слово подтверждения; удаляет файлы и пользователя (каскад по всем таблицам); последнего админа удалить нельзя | `delete-account` |
| Действия администратора | Все проверяются на сервере: RLS `*_admin` + `is_admin()` внутри каждой SQL-функции; смены статуса и ролей пишутся в `admin_audit` | `0001`, `0002` |

## Что стоит включить дополнительно
- Supabase **Auth → Attack protection**: CAPTCHA (hCaptcha/Turnstile) для регистрации, если появится спам.
- Supabase **Leaked password protection** (проверка по HaveIBeenPwned) — на платных тарифах.
- Регулярно смотрите **Advisors → Security** в панели Supabase.
- MFA для аккаунта администратора (Supabase Auth поддерживает TOTP).
