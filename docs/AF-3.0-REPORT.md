## 4. База данных

**`public.user_preferences`** (1 строка на пользователя, FK → `profiles(id) ON DELETE CASCADE`):
`notifications`, `ai`, `appearance`, `workspace`, `experimental` (jsonb), `created_at`, `updated_at`.
В колонках хранятся только изменённые значения; значения по умолчанию — `af_pref_defaults()`, подмешиваются при чтении.
Не хранит пароли, ключи, токены, роли.

- Триггер `trg_profile_preferences` создаёт строку для нового профиля; backfill `INSERT … ON CONFLICT DO NOTHING` ничего не перезаписывает.
- RLS: пользователь читает только свою строку. Прямые INSERT/UPDATE/DELETE для `authenticated` запрещены.
- RPC (только `authenticated`, `anon` запрещён, `SECURITY DEFINER`, фиксированный `search_path`, `auth.uid()`):
  - `get_my_preferences()`
  - `save_my_preferences(p_category, p_patch, p_expected)` — allowlist категорий и ключей, проверка типов и значений, неизвестные поля отклоняются, `user_id` от клиента не принимается, конфликт по `updated_at` → `pref_conflict`
  - `reset_my_preferences(p_category)` — сбрасывает только одну категорию

**`public.ai_request_events`** — журнал минутного лимита. RLS включён, политик нет, клиентам доступ закрыт (только service_role).
- `ai_rate_consume(user, limit)` — `pg_advisory_xact_lock` на пользователя: параллельные запросы не обходят лимит; возвращает used / remaining / retry_after; удаляет события старше 24 ч.
- `ai_rate_peek(user, limit)` — то же без записи (для статистики).
- `ai_refund(user, day)` — возврат дневного запроса.
- Все три + существующий `ai_consume` — только service_role.

## 5. Как сохраняются настройки

1. Переключатель меняется → интерфейс применяется сразу (optimistic) → через 60–400 мс одна RPC на категорию (повторные запросы сериализуются).
2. «Сохранено» показывается **только после ответа Supabase**.
3. Ошибка → значение откатывается, показывается понятная причина (нет сети / конфликт / миграция не применена / недопустимое значение).
4. Конфликт с другим устройством → загружаются свежие данные; изменение применяется повторно только если другое устройство не меняло тот же параметр, иначе — предупреждение, ничего молча не перезаписывается.
5. Формы (имя, пароль, email) сохраняются кнопкой, как раньше.

## 6. Между устройствами

- Аккаунтные (`user_preferences`, а также `theme`/`lang`/`notify_*` в profiles) — одинаковы на всех устройствах.
- Устройство (`af.fx`, `af.q3d`, `af.glow`) — как раньше, локально; помечены «Это устройство».
- Локальный снимок внешнего вида — только чтобы не было вспышки при загрузке; привязан к `user_id`, удаляется при выходе и смене аккаунта.

**AF AI quota:**
1. Проверка сообщения, диалога и мудборда (ничего не списывается).
2. Минутный лимит — атомарно (событие остаётся даже при ошибке, чтобы повторы не перегружали Gemini).
3. Дневной запрос резервируется через `ai_consume()`.
4. Генерация. Подтверждённая ошибка Gemini (HTTP-ошибка / таймаут) → `ai_refund()`, в ответе `refunded: true`.
5. Каждый ответ и каждая ошибка 429/503/502 содержат свежий `quota`-снимок — интерфейс обновляется сразу.
6. Сброс — полночь UTC (`reset_at`), браузер показывает «Сброс через 4 ч 18 мин» и точное локальное время.
7. `daily_limit = 0` — запросов нет (не безлимит).
8. Обновление: при открытии AI и настроек, после ответа, после 429, при возврате на вкладку, раз в 45 с на странице AI; обратный отсчёт — локально раз в секунду; таймеры очищаются при уходе.
9. Ошибка сети — последние известные цифры остаются, показывается «Не удалось обновить статистику» + «Повторить»; текст в поле ввода не теряется.

## 10. Что сделать владельцу Supabase

1. **SQL Editor** (отключите автоперевод страницы):
   - выполнить `supabase/migrations/20261126000001_user_preferences.sql` → в конце строка `table_ok, rls_ok, rows_match, client_cannot_write` = **true**;
   - выполнить `supabase/migrations/20261126000002_ai_quota.sql` → все столбцы **true**.
2. **Edge Functions → ai-chat → Code**: вставить весь `supabase/dashboard/ai-chat.ts` → Deploy (Verify JWT — OFF, как раньше).
3. **Edge Functions → notify → Code**: вставить `supabase/dashboard/notify.ts` (v4) → Deploy (Verify JWT — OFF).
4. Проверка: выполнить `supabase/tests/3.0-settings-quota.test.sql` → последняя строка `all_tests_passed = true` (всё откатывается, данные не меняются).
5. Загрузить в репозиторий **содержимое** папки `AF-STUDIO/` из архива → подождать 1–10 мин → Ctrl+Shift+R.

Новые секреты не нужны. До шагов 1–3 сайт продолжает работать: настройки показывают баннер «нужна миграция» и значения по умолчанию, AI использует прежний минутный лимит.

## 12. Оставшиеся вопросы

- Размер текста использует CSS `zoom` для области контента: в современных браузерах работает корректно, в очень старых Safari возможны неточности.
- Персонализация Обзора использует `:has()` (Chrome 105+, Safari 15.4+, Firefox 121+).
- Список аккаунтов для быстрого переключения — только email и имя на этом устройстве; переключение требует повторного входа (несколько одновременных сессий Supabase в одной вкладке не поддерживает).
- Email-уведомления по-прежнему требуют RESEND_API_KEY + MAIL_FROM.
