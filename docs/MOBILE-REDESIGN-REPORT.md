# AF STUDIO — мобильный аудит и редизайн

> **Честно о проверке.** В среде, где я работаю, браузер запустить нельзя: Playwright установлен, но системный
> запрет на запуск процессов не даёт ему стартовать Chromium. Поэтому **визуально на 320–768 px я ничего не видел**.
> Сделано: статический аудит стилей и разметки всех разделов, мобильный слой, unit-тесты (37/37), проверка синтаксиса
> 58 модулей и **готовый Playwright-тест** `tests/mobile/`, который проверяет все ширины и маршруты на вашем компьютере
> за пару минут (§6). Работа **не объявляется завершённой**, пока этот тест не прогнан на реальном сайте.

Проверено, что уже было в порядке: поля ввода 16 px (без зума iOS), нижняя навигация из 5 пунктов,

пауза WebGL вне экрана (IntersectionObserver), `prefers-reduced-motion` в основных стилях.
Меню админки на телефоне открывается кнопкой в шапке (она показывается встроенным стилем ≤ 860 px).

## 2. Что сделано

**Новые файлы**
- `css/mobile.css` — мобильный слой. **Все правила внутри `@media (max-width: 860/600/380px)` или `(hover: none)`**,
  поэтому десктоп не меняется (это проверяет unit-тест).
- `js/core/mobile.js` — видимая высота экрана `--af-vvh` (с клавиатурой), класс `af-kb-open`, прокрутка поля над клавиатурой,
  свайп влево закрывает боковое меню.
- `tests/mobile/mobile.spec.mjs`, `tests/mobile/playwright.config.mjs` — E2E-проверка на 320, 360, 375, 390, 414, 430, 768 и 1440 px.

**Изменённые файлы (минимально)**
- `index.html`, `admin.html` — подключён `css/mobile.css`.
- `js/main.js`, `js/admin/main.js` — `initMobile()`.
- `js/views/lab.js` — ограничения WebGL на телефоне, запасной полноэкранный режим, сенсорная подсказка, очистка обработчика.
- `js/views/project-detail.js` — предпросмотр изображений (используется в «Файлах» и в проекте).
- `js/core/i18n.js` — `lab.hintTouch`, `files.preview` (RU/EN).
- `tests/unit.test.mjs` — 3 новых теста.

**По разделам (≤ 860 px)**
- Навигация: шапка 56 px + safe area, заголовок обрезается многоточием; нижняя панель 56 px, активная иконка подсвечена,
  отклик на нажатие, прячется при открытой клавиатуре; шторка 88vw, пункты 48 px.
- Модальные окна: листы снизу с «ручкой», большие окна на весь экран, шапка и кнопки «липкие», кнопки делят ширину.
- AF AI: чат от края до края, высота по видимой области, поле ввода над клавиатурой, кнопки 44 px, история — выезжающая панель,
  меню «+» на всю ширину, «светофор» сохранён.
- 3D Lab: сцена 300–520 px, один палец вращает, два масштабируют, кнопки HUD 44 px, полноэкранный режим и на iPhone.
- Конструктор: прокручиваемая лента 7 этапов, «липкая» панель «Назад / ИИ / Далее», миниатюры 3 в ряд, кнопки удаления 44 px.
- Файлы: ряды с кнопками 44 px, плитка 2 в ряд, предпросмотр. Загрузка через системный выбор файла: на iPhone и Android он
  предлагает галерею, камеру и файлы.
- Сообщения: высота по видимой области, «липкое» поле ввода.
- Портфолио, Услуги, Калькулятор, Проекты, Мудборд, Уведомления, Настройки, Вход, Админка — одна колонка, полноширинные
  действия, горизонтальные ленты вместо переносов, крупные поля (48–52 px), KPI админки 2 в ряд.
- Производительность: на телефонах короче анимации появления, легче размытие фона, ограничения WebGL; при
  `prefers-reduced-motion` переходы панели, шторки и листов отключаются.

## 3. Десктоп
Мобильный слой не содержит правил вне мобильных медиа-запросов. В `lab.js` формула для десктопа та же
(`high → 2×, medium → 1.5×, low → 1×`, тени 2048/1024). Единственное новое на десктопе — предпросмотр изображения по клику
на миниатюру файла (раньше клик ничего не делал).

## 4. Тесты, выполненные здесь
- Unit: **37/37** (новые: мобильный CSS только в мобильных медиа-запросах и не ставит `overflow-x: hidden` на body;
  определение клавиатуры; подключение помощников, ограничения 3D Lab, предпросмотр, переводы).
- Синтаксис 58 JS-модулей и Playwright-теста; все импорты разрешаются.
- Все 150 классов из `css/mobile.css` существуют в разметке, кроме 2 запасных (`af-grid--4`, `ov-stats`) — безвредны.

## 5. Не проверено здесь
Реальный вид на телефонах, поведение клавиатуры iOS/Android, жесты в 3D Lab, FPS WebGL, отсутствие переполнения на каждом
маршруте. Для этого — §6 или проверка на своём телефоне.

## 6. Как прогнать мобильную проверку (на вашем компьютере)
```bash
cd AF-STUDIO
npm i -D @playwright/test
npx playwright install chromium webkit
# только экран входа:
npx playwright test -c tests/mobile/playwright.config.mjs
# весь сайт (тестовый аккаунт; ничего не создаётся и не отправляется):
AF_EMAIL=test@example.com AF_PASSWORD=... npx playwright test -c tests/mobile/playwright.config.mjs
```
Результат: `tests/mobile/report.json` (переполнение по каждому маршруту и ширине, список элементов < 44 px) и скриншоты в
`tests/mobile/shots/`. Пришлите `report.json` или скриншоты — исправлю всё, что найдётся.
В Windows PowerShell переменные задаются так: `$env:AF_EMAIL="..."; $env:AF_PASSWORD="..."`.
